# 项目架构说明书

## 一、系统概述

收纳小助手是一款基于Flutter开发的Android NFC标签管理应用，旨在帮助用户通过NFC标签管理物品存放信息。用户可以将物品名称存储到NFC标签中，并通过手机快速读取和管理这些信息。

## 二、技术架构

### 2.1 技术栈

- **框架**: Flutter 3.47.x（stable，Dart SDK ≥ 3.0）
- **语言**: Dart
- **目标平台**: Android（主）、iOS/Web/桌面（脚手架已具备）
- **NFC库**: nfc_manager ^3.3.0
- **本地数据库**: sqflite ^2.3.0
- **媒体处理**: image_picker ^1.0.4 / image ^4.1.3 / video_compress ^3.1.2 / video_thumbnail ^0.5.3 / video_player ^2.7.0
- **其他**: path_provider、uuid ^4.2.1、permission_handler ^11.1.0、intl ^0.18.1
- **Android 构建链**: Gradle 8.14 / AGP 8.11.1 / Kotlin 2.2.20 / 完整 JDK 21 / compileSdk 36
- **最低Android版本**: API 21 (Android 5.0)

### 2.2 项目结构

```
lib/
├── main.dart                       # 应用入口
├── data/
│   └── data_manager.dart           # 数据管理门面（聚合各服务，单例）
├── models/                         # 数据模型
│   ├── tag_record.dart             # 容器/标签记录
│   ├── item_record.dart            # 物品记录
│   └── media_record.dart           # 媒体内存 DTO（不对应数据表）
├── services/                       # 服务层
│   ├── nfc_service.dart            # NFC服务（单例）
│   ├── database_service.dart       # SQLite数据库服务（单例）
│   └── media_service.dart          # 媒体压缩/缩略图/清理服务（单例）
└── views/                          # 视图层
    ├── home_page.dart              # 容器详情/物品列表主页
    ├── container_list_page.dart    # 容器列表页
    ├── item_info_page.dart         # 物品信息页（add/view/edit/remove）
    └── settings_page.dart          # 设置页（存储管理/数据清理）
```

### 2.3 架构分层

#### 表示层 (Views)
- **home_page.dart**: 容器详情/物品列表主页
  - NFC扫描识别容器（新标签弹窗命名、已有标签加载物品）
  - 物品列表展示（按创建时间倒序）
  - 生命周期监听（resumed 重启 NFC 会话，paused/detached 停止）
  - 存入物品、清空容器操作
  
- **container_list_page.dart**: 容器列表页
  - 展示全部已创建容器，点击进入对应容器主页

- **item_info_page.dart**: 物品信息页面
  - 四种模式：新增（add）、查看（view）、编辑（edit）、取出（remove）
  - 左右滑动切换同容器内物品，带滑动动画与位置指示
  - `_currentItemData` 记录当前展示物品，编辑/删除只作用于它
  - 图片/视频的选择、拍摄、压缩与全屏查看

- **settings_page.dart**: 设置页
  - 存储占用查看、孤儿媒体清理、清除所有数据

#### 服务层 (Services)
- **nfc_service.dart**: NFC操作服务（单例）
  - NFC可用性检测、会话管理、硬件标签ID读取
  - NDEF读取/写入、标签格式化、重试机制（注：NDEF接口已实现，当前业务以硬件ID+本地数据库为主）

- **database_service.dart**: 数据库服务（单例）
  - tags/items 两表管理、索引与外键（级联删除）
  - 标签更新/删除按 `tagId` 匹配

- **media_service.dart**: 媒体服务（单例）
  - 图片压缩（最长边1024px、JPEG 80%）、视频压缩、缩略图生成
  - 孤儿媒体文件清理

#### 数据层 (Data/Models)
- **data_manager.dart**: 门面层（单例），聚合上述三个服务，向视图层提供统一的增删改查接口
- **models/**: TagRecord / ItemRecord 提供 toMap/fromMap/copyWith 持久化序列化；MediaRecord 为纯内存 DTO（媒体采集返回值，不对应数据表）

### 2.4 数据流

```
NFC硬件 → NfcService（读取硬件标签ID）→ DataManager → DatabaseService（tags/items）
                                              ↓
页面组件（Views）← 状态更新（setState/ValueNotifier）← 界面刷新
        ↓
MediaService（拍照/选图 → 压缩 → 应用私有目录）→ 路径存入 items 表
```

核心业务流：扫描标签 → 以 tagId 查询容器（新标签则命名入库）→ 加载该容器物品 → 物品详情页可左右滑动切换，编辑/删除始终作用于当前展示物品。

## 三、核心模块设计

### 3.1 NFC服务模块

#### 主要功能
- `isNfcAvailable()`: 检查设备NFC是否可用
- `startSession()`: 启动NFC扫描会话
- `stopSession()`: 停止NFC会话
- `readTag()`: 读取标签数据
- `writeTextToTag()`: 写入文本数据（带重试）
- `formatTagToNdef()`: 格式化标签为NDEF格式

#### 状态管理
- `_isSessionStarted`: 会话状态标志
- `_lastTagId`: 最近一次标签ID
- 定期标签存在性检测机制

### 3.2 页面模块

#### 物品列表页面 (HomePage)
- 状态管理：`setState` 结合 `ValueNotifier` 管理 NFC 结果与扫描状态
- 列表展示：`ListView.builder` 实现当前容器物品列表
- NFC 会话：随应用生命周期（resumed/paused/detached）启停
- 容器识别：新标签弹窗命名后入库，已有标签直接加载物品

#### 物品信息页面 (ItemInfoPage)
- 模式枚举：`ItemInfoMode { add, view, edit, remove }`
- 操作状态：`_isOperating` 防止重复提交
- 数据传递：构造函数传入 tagId、模式与初始物品数据
- **当前物品状态**：`_items` + `_currentIndex` 承载同容器物品列表；`_currentItemData` 指向当前展示物品，初始化时取入参，滑动时由 `_updateUIWithItem` 同步；编辑保存与取出删除均以其 id 为准

## 四、关键设计决策

### 4.1 NFC会话管理
- 使用`NfcManager`进行会话管理
- 会话启动后持续监听标签
- 支持错误提示和状态更新

### 4.2 数据存储格式
- 业务数据存储于本地 SQLite（storage_assistant.db），时间字段使用 ISO8601 文本
- 标签与物品通过 NFC 硬件标签 ID（`tagId`，字符串）关联，物品 id 为 uuid
- NfcService 已具备 NDEF Text Record（UTF-8）读写与标签格式化能力，当前主流程以"硬件 ID + 本地数据库"为准，NDEF 写入尚未接入 UI

### 4.3 标签ID验证
- 记录当前标签ID
- 写入前验证标签是否更换
- 更换时提示用户确认

### 4.4 错误处理
- 写入重试机制（最多3次）
- 容量超限检测
- 标签类型识别
- 用户友好的错误提示

### 4.5 标签主键策略（tagId 业务键）
- `TagRecord` 创建时 `id` 与 `tagId` 取相同值（NFC 硬件标签 ID）
- `updateTag`/`deleteTag` 一律按 `tagId` 匹配而非 `id`，避免历史数据 id 为空时 `WHERE id = NULL` 导致的静默失败
- items 表外键指向 tags(tagId) 并配置 `ON DELETE CASCADE`

### 4.6 滑动操作目标一致性
- 物品详情页滑动切换会改变当前展示物品，编辑/删除操作必须读取"当前展示物品"而非页面初始入参
- 通过 `_currentItemData` 单一数据源实现，杜绝误改、误删其他物品

## 六、Android 构建环境

| 项 | 版本/值 | 说明 |
|----|---------|------|
| Flutter | 3.47.x stable | 国内镜像 flutter-io.cn |
| JDK | 完整 JDK 21 | 必须含 jlink；Java 25 与 Gradle 8.14 不兼容；精简 JBR 缺 jlink |
| Gradle | 8.14 | wrapper 指向腾讯云镜像 |
| AGP | 8.11.1 | settings.gradle.kts 声明 |
| Kotlin | 2.2.20 | Flutter 3.47 最低要求（原 1.9.0/2.0.0 无法构建） |
| Android SDK | compileSdk 36 / build-tools 36.0.0 | 另需 platform-tools、CMake 3.22.1 |

**国内网络适配**：
- `android/build.gradle.kts` 的 allprojects 前置阿里云（google/central）与华为云 Maven 镜像
- 全局 `~/.gradle/init.d/` 脚本仅移除已关停的 jcenter（老插件 video_thumbnail 声明，访问会永久挂起）；不可用 init 脚本注入仓库，Flutter composite build 的 `FAIL_ON_PROJECT_REPOS` 会拒绝
- `settings.gradle.kts` 的 pluginManagement 保留官方 google/mavenCentral/gradlePluginPortal（dl.google.com 直连速度良好）
