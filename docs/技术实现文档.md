### 1. NFC功能实现

#### NFC会话管理
```dart
// NFC服务核心实现
class NFCService {
  Future<void> startSession({
    required Function(NfcTag) onTagDiscovered,
  }) async {
    await NfcManager.instance.startSession(
      onDiscovered: (tag) async {
        _lastTag = tag;
        onTagDiscovered(tag);
      },
      invalidateAfterFirstRead: true, // 防止系统应用干扰
    );
  }
}
```

**关键优化点**：
- 使用`invalidateAfterFirstRead: true`避免系统应用干扰

#### 动画系统优化
```dart
// 滑动动画实现
void _animateSlide() {
  const duration = Duration(milliseconds: 300);
  final controller = AnimationController(
    duration: duration,
    vsync: Navigator.of(context), // 使用Navigator作为vsync
  );
  
  final animation = CurvedAnimation(
    parent: controller,
    curve: Curves.easeInOut,
  );
  
  animation.addListener(() {
    setState(() {
      _slideOffset = _slideOffset * (1 - animation.value);
    });
  });
  
  animation.addStatusListener((status) {
    if (status == AnimationStatus.completed) {
      setState(() {
        _slideOffset = 0.0; // 动画完成后重置位置
        _slideDirection = SlideDirection.none;
      });
      controller.dispose();
    }
  });
  
  controller.forward();
}
```

**动画系统特点**：
- 使用`Transform.translate`替代`SlideTransition`，避免内容消失问题
- 动画控制器使用`Navigator.of(context)`作为vsync，提高稳定性
- 实现平滑的缓动动画效果
- 动画完成后自动清理资源

### 3. 数据持久化

#### 数据库设计
应用包含三张表：`tags`（容器/标签）、`items`（物品）、`media`（媒体记录预留）。标签与物品为一对多关系，通过 `tagId`（NFC 硬件标签 ID，字符串）关联。

```dart
// 物品数据模型（id 为 uuid 字符串，tagId 为 NFC 标签 ID 字符串）
class ItemRecord {
  String? id;            // uuid，创建时由 DataManager 生成
  String? tagId;         // 关联的 NFC 标签 ID（业务外键）
  String itemName;       // 物品名称（为空时保存以时间戳 yyyyMMddHHmmss 兜底）
  String? remark;
  String? imagePath;
  String? videoPath;
  DateTime createdAt;
  DateTime? updatedAt;   // 编辑时更新
}

// 标签数据模型（关键约定：id 与 tagId 始终相同，均为 NFC 硬件标签 ID）
class TagRecord {
  String? id;
  String tagId;
  String tagName;
  DateTime createdAt;
  DateTime lastAccessAt;
}
```

#### 数据操作接口
```dart
// 数据管理器核心方法（tagId 为 String 类型的 NFC 标签 ID）
class DataManager {
  Future<List<ItemRecord>> getItemsByTag(String tagId) async {
    final db = await database;
    final List<Map<String, dynamic>> maps = await db.query(
      'items',
      where: 'tagId = ?',
      whereArgs: [tagId],
      orderBy: 'createdAt DESC',
    );

    return List.generate(maps.length, (i) {
      return ItemRecord.fromMap(maps[i]);
    });
  }
}
```

> **设计约定**：标签表的更新与删除一律按 `tagId` 匹配（而非 `id`）。`tagId` 是始终非空的业务唯一键，按它匹配可兼容历史数据；`createTag` 创建记录时同时设置 `id = tagId`，保证两个字段一致。

## 🚨 技术问题与解决方案

### 问题1: NFC标签识别冲突

**问题描述**：NFC标签贴近时系统弹出备忘录应用

**解决方案**：
1. **Android配置优化**：
   - 设置`launchMode="singleTop"`
   - 添加正确的intent-filter
   - 在MainActivity中处理NFC intent

2. **NFC会话管理**：
   - 使用`invalidateAfterFirstRead: true`
   - 优化session启动和停止时机
   - 添加标签缓存机制

### 问题2: 滑动动画内容消失

**问题描述**：滑动后内容消失，只显示标题

**解决方案**：
1. **动画实现方式变更**：
   - 从`SlideTransition`改为`Transform.translate`
   - 使用更简单的动画控制逻辑

2. **动画执行顺序优化**：
   ```dart
   void _nextItem() {
     if (_currentIndex < _items.length - 1) {
       // 1. 先更新内容
       setState(() {
         _currentIndex++;
         _updateUIWithItem(_items[_currentIndex]);
       });
       
       // 2. 再执行动画
       _animateSlide();
     }
   }
   ```

### 问题3: 动画控制器资源泄露

**解决方案**：
```dart

```

### 问题4: 滑动切换物品后，编辑/删除作用于错误的物品（严重缺陷）

**问题描述**：物品详情页支持左右滑动切换同容器内的物品，但编辑保存和取出删除仍读取页面初始入参 `widget.itemData['id']`。用户滑动到 B 物品后执行"修改"或"取出"，实际操作的是最初打开的 A 物品，造成数据错乱。

**根因**：UI 展示数据源（`_items[_currentIndex]`）与操作目标数据源（`widget.itemData`）分离，滑动时只更新了前者。

**解决方案**：引入"当前展示物品"状态字段，作为编辑/删除的唯一数据源，并在每次切换时同步：
```dart
class _ItemInfoPageState extends State<ItemInfoPage> {
  List<Map<String, dynamic>> _items = [];
  int _currentIndex = 0;
  Map<String, dynamic>? _currentItemData; // 滑动后更新，编辑/删除只认它

  @override
  void initState() {
    _currentItemData = widget.itemData; // 初始值为入参
  }

  void _updateUIWithItem(Map<String, dynamic> item) {
    _currentItemData = item; // 切换时同步操作目标
    // ...刷新名称、备注、图片、视频
  }
}
```
`_onDelete` 与编辑模式的 `_onSave` 一律从 `_currentItemData!['id']` 取目标 ID，不再引用 `widget.itemData`。

**设计原则**：同一时刻"所见"与"所操作"必须指向同一数据源，杜绝展示状态与操作状态分叉。

### 问题5: 容器（标签）删除/更新静默失败（严重缺陷）

**问题描述**：部分创建路径（`createTag`）未给 `TagRecord.id` 赋值（为 null），而 `updateTag`/`deleteTag` 按 `id` 列匹配，生成的 SQL 为 `WHERE id = NULL`，永远不命中，导致容器重命名、删除和"清除所有数据"静默失效。

**解决方案（双重保险）**：
1. 统一创建路径：`createTag` 也设置 `id = tagId`，与 `getOrCreateTag` 的兜底逻辑保持一致。
2. 匹配条件改用业务唯一键：
```dart
// database_service.dart
Future<int> updateTag(TagRecord tag) =>
    db.update('tags', tag.toMap(), where: 'tagId = ?', whereArgs: [tag.tagId]);

Future<int> deleteTag(String tagId) =>
    db.delete('tags', where: 'tagId = ?', whereArgs: [tagId]);
```
按 `tagId` 匹配对历史存量数据同样生效；`clearAllData` 中同步改用 `tag.tagId`。

### 问题6: Android 构建在国内网络与新版 JDK 下失败

**问题与对策汇总**（均已在工程配置中落地）：

| 现象 | 根因 | 对策 |
|------|------|------|
| `Java 25 incompatible with Gradle 8.14` | 新版 Android Studio 捆绑 JBR 为 Java 25 | 使用完整 **JDK 21**（`flutter config --jdk-dir`） |
| `jlink.exe does not exist` / JdkImageTransform 失败 | IDE 精简版 JRE 缺少 jlink 等 JDK 工具 | 改用完整版 JDK（如 Temurin 21），不能用精简 JBR |
| `Kotlin version 2.0.0 is lower than minimum 2.2.20` | Flutter 3.47 提升了最低 Kotlin 版本 | `settings.gradle.kts` 升级 Kotlin 插件至 **2.2.20** |
| Gradle 发行版下载长时间无进度 | services.gradle.org 国内不稳定 | wrapper 改指腾讯云镜像 `mirrors.cloud.tencent.com/gradle` |
| 构建卡在解析依赖（连接 jcenter.bintray.com） | 老插件 video_thumbnail 仍声明已关停的 jcenter | 全局 init 脚本（`~/.gradle/init.d/`）移除 jcenter；项目 Maven 仓库前置阿里云/华为云镜像 |

> 注意：Flutter 工具的 composite build 使用 `FAIL_ON_PROJECT_REPOS` 模式，**全局 init 脚本只能移除仓库、不能注入仓库**，否则构建报错；插件解析仓库必须保留在项目 `settings.gradle.kts` 的 `pluginManagement` 中（官方 `google()`/`mavenCentral()`/`gradlePluginPortal()`）。
