## 🎯 系统概述

### 项目背景
Storage Assistant是一个基于NFC技术的智能仓储管理应用，旨在解决传统仓储管理中物品识别困难、信息记录不便的问题。

### 系统目标
- **快速识别**：通过NFC技术实现物品的秒级识别
- **信息管理**：完整记录物品的基本信息和多媒体内容
- **便捷操作**：提供直观的用户界面和流畅的操作体验
- **跨平台支持**：支持Android和iOS平台

### 技术选型
| 技术领域 | 技术选型 | 选择理由 |
|---------|---------|---------|
| 前端框架 | Flutter | 跨平台开发，高性能渲染 |
| 数据库 | SQLite | 轻量级，本地存储，无需网络 |
| NFC支持 | nfc_manager | 功能完整，社区活跃 |
| 多媒体 | image_picker + video_player | 官方推荐，稳定性好 |

## 🏗️ 架构设计

### 整体架构
```
┌─────────────────────────────────────────────────────────────┐
│                       表示层 (Presentation)                   │
├─────────────────────────────────────────────────────────────┤
│   HomePage   ItemInfoPage  ContainerListPage  SettingsPage  │
│   (容器详情)    (物品详情)      (容器列表)         (设置页面)   │
└─────────────────────────────────────────────────────────────┘
                               │
┌─────────────────────────────────────────────────────────────┐
│                       业务层 (Business)                      │
├─────────────────────────────────────────────────────────────┤
│   NFCService     MediaService     DatabaseService           │
│   (NFC服务)      (媒体服务)       (数据库服务)                │
└─────────────────────────────────────────────────────────────┘
                               │
┌─────────────────────────────────────────────────────────────┐
│                       数据层 (Data)                         │
├─────────────────────────────────────────────────────────────┤
│   DataManager     Models          Database                  │
│   (数据管理)      (数据模型)       (数据库)                   │
└─────────────────────────────────────────────────────────────┘
```

### 架构原则
1. **分层架构**：清晰的职责分离
2. **依赖倒置**：高层模块不依赖低层模块
3. **单一职责**：每个模块只负责一个功能
4. **开闭原则**：对扩展开放，对修改关闭
5. **状态一致性**：页面展示状态与操作目标必须共享同一数据源（如物品详情页的 `_currentItemData`）；数据库写操作以始终非空的业务键（`tagId`）为匹配条件，避免静默失败

## 🔧 模块设计

### 1. 表示层模块

#### HomePage模块
**职责**：
- 显示NFC标签识别状态
- 展示物品列表
- 提供添加物品入口

**核心状态**：
```dart
class HomePage extends StatefulWidget {
  @override
  _HomePageState createState() => _HomePageState();
}

class _HomePageState extends State<HomePage> {
  String? _currentTagId;
  List<ItemRecord> _items = [];
  bool _isLoading = false;
}
```

#### ItemInfoPage模块
**职责**：
- 显示物品详细信息
- 支持左右滑动导航
- 提供编辑和删除功能

**核心特性**：
- 手势检测系统
- 动画控制系统
- 多媒体展示系统
- **操作目标一致性**：以 `_currentItemData` 字段记录当前展示物品，滑动切换时同步更新；编辑与删除只作用于该字段指向的物品，确保"所见即所操作"

### 2. 业务层模块

#### NFCService模块
**职责**：
- 管理NFC会话
- 处理标签识别
- 防止系统应用干扰

**核心方法**：
```dart
class NFCService {
  Future<void> startSession({required Function(NfcTag) onTagDiscovered});
  Future<void> stopSession();
  Future<String?> getTagId(NfcTag tag);
}
```

#### MediaService模块
**职责**：
- 图片选择和处理
- 视频录制和播放
- 文件路径管理

### 3. 数据层模块

#### DataManager模块
**职责**：
- 提供统一的数据访问接口
- 管理数据库连接
- 处理数据转换

**核心接口**：
```dart
class DataManager {
  Future<TagRecord> createTag(String tagId, String tagName);
  Future<List<ItemRecord>> getItemsByTag(String tagId);
  Future<ItemRecord> createItem(ItemRecord item);
  Future<void> updateItem(ItemRecord item);
  Future<void> deleteItem(String itemId);
}
```

## 💾 数据设计

### 数据库表设计

数据库文件 `storage_assistant.db`（version 1），共两张表。所有主键/外键均为 TEXT：标签使用 NFC 硬件标签 ID，物品使用 uuid。

#### tags表（容器/标签表）
| 字段名 | 类型 | 说明 | 约束 |
|-------|------|------|------|
| id | TEXT | 记录主键 | PRIMARY KEY，创建时与 tagId 相同 |
| tagId | TEXT | NFC硬件标签ID | NOT NULL UNIQUE（业务唯一键） |
| tagName | TEXT | 容器名称 | NOT NULL |
| createdAt | TEXT | 创建时间（ISO8601） | NOT NULL |
| lastAccessAt | TEXT | 最近访问时间 | NOT NULL |

> 标签的更新与删除统一按 `tagId` 匹配（非 `id`），保证历史数据（可能 id 为空）也能被正确操作。

#### items表（物品表）
| 字段名 | 类型 | 说明 | 约束 |
|-------|------|------|------|
| id | TEXT | 物品ID（uuid） | PRIMARY KEY |
| tagId | TEXT | 关联NFC标签ID | NOT NULL，FOREIGN KEY→tags(tagId) ON DELETE CASCADE |
| itemName | TEXT | 物品名称 | NOT NULL（空名保存时以时间戳 yyyyMMddHHmmss 兜底） |
| imagePath | TEXT | 图片路径 | NULLABLE |
| videoPath | TEXT | 视频路径 | NULLABLE |
| remark | TEXT | 备注信息 | NULLABLE |
| createdAt | TEXT | 创建时间（ISO8601） | NOT NULL |
| updatedAt | TEXT | 更新时间（ISO8601） | NOT NULL |

索引：`idx_items_tagId (tagId)`、`idx_tags_tagId (tagId)`。

#### media表（已于 v1.1.1 移除）

> 说明：早期版本曾建 media 预留表（id/filePath/type/thumbnailPath/createdAt），但其增删查方法从未被业务调用——媒体路径直接存于 items 表的 imagePath/videoPath 字段。为避免误导维护者，该表及 MediaRecord 的 fromMap 已于 v1.1.1 从代码中移除，MediaRecord 现仅作为媒体采集的内存 DTO 使用。如需"一个物品多个媒体"，应重新设计关联方案而非恢复旧表。

#### 数据关系设计
```
NFC标签 tags (1)
    │  tagId（一对多，级联删除）
    └── 物品记录 items (N)
          ├── 图片文件 (0:1) → imagePath
          └── 视频文件 (0:1) → videoPath（含缩略图）
```

### 数据流设计

#### 物品添加流程
```
用户操作 → 数据验证 → 文件保存 → 数据库写入 → 界面更新
```

#### 标签识别流程
```
NFC事件 → 标签解析 → 数据查询 → 界面展示
```

## 🚀 部署设计

### 开发环境部署

#### 环境要求
- Flutter SDK 3.47（stable）
- **完整 JDK 21**（必须含 jlink，不能使用 IDE 精简版 JRE；勿用 Java 25，与 Gradle 8.14 不兼容）
- Android SDK（compileSdk 36、build-tools 36.0.0、platform-tools、CMake 3.22.1）
- Android Studio 或其他 IDE
- 物理设备（支持NFC，已开启USB调试）
- Windows 下首次构建需开启"开发者模式"（符号链接支持）

#### 国内网络配置
- Flutter/Dart 包镜像环境变量：`FLUTTER_STORAGE_BASE_URL=https://storage.flutter-io.cn`、`PUB_HOSTED_URL=https://pub.flutter-io.cn`
- Gradle 发行版：`gradle-wrapper.properties` 指向腾讯云镜像
- Maven 依赖：`android/build.gradle.kts` 前置阿里云/华为云镜像
- 老插件残留的 jcenter 声明由 `~/.gradle/init.d/` 全局脚本移除（jcenter.bintray.com 已关停，否则构建会永久挂起）

#### 部署步骤
1. **环境配置**：安装Flutter SDK、完整JDK 21、Android SDK，并配置 `flutter config --jdk-dir/--android-sdk`
2. **依赖安装**：运行`flutter pub get`
3. **平台初始化**：运行`flutter create .`（如需要）
4. **设备连接**：连接支持NFC的Android设备并授权USB调试
5. **应用运行**：运行`flutter run`（或先 `flutter build apk --debug` 再安装）
